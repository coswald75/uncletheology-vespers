# Operations

How these two projects are built, hosted, and published. If you're picking this
up cold, read this top to bottom once — it explains the whole machine.

---

## 1. What this is

Two audio brands, run as **static websites generated by Python**:

| | Uncle Theology | Vespers |
|---|---|---|
| Site | [uncletheology.com](https://uncletheology.com) | [vesperstonight.com](https://vesperstonight.com) |
| What | Sermon-based AI **music** — albums + a podcast (**UncleTheology Radio**) | A late-night **talk** podcast: great ideas, Scripture, public-domain books |
| Voice | Reformed, playful, "theology you can nod your head to" | Calm, nocturnal — *"small music, big talk"* |
| Generator | `uncletheology-site/build.py` | `vespers-site/build.py` |
| Folder | [`uncletheology-site/`](uncletheology-site/) | [`vespers-site/`](vespers-site/) |

They're siblings on purpose (same label, **Oswald Records**; same generator
shape; same hosting), which is why they share one repo.

## 2. The shared machine (both sites)

**Generator → static files → Cloudflare.** Each site is a Python script that
writes a folder of plain HTML into `public/`. Cloudflare serves that folder.

- **No framework, no build tools, no dependencies.** The generators use only the
  Python standard library (`html`, `json`, `os`, `re`, `shutil`). If you have
  Python 3, you can build.
- **Hosting = Cloudflare** (account: chris@sovgracekc.org). Each site is a
  Cloudflare Worker-on-assets, configured in its `wrangler.jsonc`, on a custom
  domain.
- **Deploy is a push to Cloudflare, not a push to GitHub.** Committing here does
  **not** update the live site. You deploy with `wrangler` (below). GitHub is
  version control / backup; Cloudflare is the live host.
- **Audio lives on Cloudflare R2**, served from `sermons-cdn.sermonsteward.com`.
  The big generated audio masters (`_audio_build/`, ~1 GB) are **git-ignored** —
  they're built locally and uploaded to R2, never committed. The websites just
  point at the R2 URLs.

### Deploying either site

```bash
cd <uncletheology-site | vespers-site>
python3 build.py        # regenerates public/
npx wrangler deploy     # pushes public/ live to Cloudflare
```

First `wrangler` run in a session may prompt you to log in to Cloudflare.

## 3. Uncle Theology — `uncletheology-site/`

### Content model
Every album is a **Python module** describing its songs, lyrics, and study
notes. `albums.py` aggregates them all into one `ALBUMS` list that `build.py`
renders.

- Album modules: `songs.py` (the original *Roots of Reason*), `john_and_them.py`,
  `barn_dance.py`, `proverbs.py`, `shadys_bach.py`, `common_grace.py`,
  `that_nazarene.py`, `sovereign_driver.py`. Newer albums are one file each;
  register a new one by importing it in `albums.py`.
- Each **song** carries a "study layer": `about`/`thesis`, `blocks` (the lyrics,
  as labeled sections), `facts`, `moves`, `terms`, `discussion`,
  `contemplation`, and `refs` (Scripture). This is what powers the per-song study
  pages — and the YouTube descriptions.
- An album may set `theme` (a palette dict) to give its pages their own identity.

### What build.py produces (into `public/`)
- `index.html` — the discography landing (album cards)
- `<album>/index.html` — album page (hero + whole-album player + tracklist)
- `<album>/<song>.html` — a song page (lyrics, Scripture, study notes, share card)
- `radio` + `podcast.xml` — **UncleTheology Radio** feed

### Audio (R2)
`https://sermons-cdn.sermonsteward.com/uncle-theology/<prefix>/<slug>.mp3`
Radio masters + art live under `.../uncle-theology/podcast/`.

### UncleTheology Radio
Each album becomes one whole-album podcast **episode** with AI-voiced spoken
intros before each track (ElevenLabs, via the audio MCP — no API keys in this
repo). Episode metadata lives in the album module's `episode` block; the feed is
`public/podcast.xml`.

## 4. Vespers — `vespers-site/`

### Content model
Episodes are defined in `vespers-site/build.py` (the `EPISODES` list, newest
first). Each episode has a title, date, slug, `audio_url` (R2), and a transcript.

- **Transcripts** live in `vespers-site/transcripts/<slug>.txt` and are rendered
  onto the episode pages.
- Audio: `https://sermons-cdn.sermonsteward.com/vespers/episodes/<slug>.mp3`

### Adding an episode
1. Drop the finished MP3 in R2 under `vespers/episodes/<slug>.mp3`
   (`npx wrangler r2 object put "sermon-steward-audio/vespers/episodes/<slug>.mp3" --file=… --remote --content-type audio/mpeg`).
2. Save the transcript to `transcripts/<slug>.txt`.
3. Add an entry to `EPISODES` in `build.py` (newest first).
4. `python3 build.py && npx wrangler deploy`.

## 5. The YouTube lyric-video pipeline (Uncle Theology)

Separate from the websites, we produce **lyric videos** for the Uncle Theology
YouTube channel ([@uncletheology](https://youtube.com/@uncletheology)). One video
per song. The current build scripts live outside this repo (in the working
scratchpad); this section documents the process so it can be rebuilt or handed
off. The recipe, per song:

1. **Get the audio + exact lyrics.** MP3 from R2 (or the DistroKid export folder);
   lyrics come from the song's `blocks` in its album module (the source of truth
   — never transcribe them).
2. **Time the lyrics to the vocal.** Run `faster-whisper` (base.en) with word
   timestamps on the MP3 for **timing only**, then anchor each lyric line to its
   real first-word onset. Whisper mishears words but times them well. For dense
   rap, pair lines into **couplets** (2 per card) and align within song sections.
3. **Render the lyric cards.** Each line/couplet is an HTML card screenshotted by
   headless Chrome as a transparent PNG, in the album's palette (eyebrow =
   "UNCLE THEOLOGY · <ALBUM>", cream serif lyric, `uncletheology.com` corner).
4. **Composite with ffmpeg.** A background image (the album cover, or a custom
   image) fills 1080p; an **always-on base layer** carries the scrim bar + border
   + branding; the lyric cards toggle on top via
   `overlay=…:enable='gte(t,s)*lt(t,e)'` (start-inclusive / end-exclusive so
   exactly one card shows at a time — this avoids a one-frame "flash" at every
   transition). Instrumental/hook gaps show the clean image (a transparent rest
   card). Mux the MP3, export H.264.
5. **Verify + publish.** Confirm sync on a few frames and that a per-frame
   brightness scan shows zero flash-dips; then upload to YouTube. On-screen
   `uncletheology.com` is a visual cue only — the **clickable** link goes in the
   video description (external card/end-screen links need YouTube Partner Program
   eligibility).

Each song also gets a **description** written from its study layer (hook +
Scripture + key terms + a discussion question + site link).

## 7. Gotchas / house rules

- **Deploy ≠ commit.** `git push` backs up code; `npx wrangler deploy` updates the
  live site. Do both.
- **Never commit `_audio_build/`** (huge) or `.wrangler/`, `node_modules/`,
  `__pycache__/`. That's what `.gitignore` is for. Audio belongs on R2.
- **Lyrics are the source of truth in the album modules** — don't rely on
  transcription for words, only for timing.
- **Disk space:** the audio-master builds are large; free space before big
  local audio/video renders.
- **Preserve the hand-crafted prose.** These sites carry a specific voice; keep
  it when editing generated copy.
